# Air Monitor / AlmatyAir

## Быстрый запуск

Откройте `Script/server-panel.cmd` двойным щелчком и нажмите «Запустить».
Сайт: http://localhost:8002/ ; проверка сервера: http://localhost:8002/api/v1/health ; API: http://localhost:8002/docs .
Панель запускает миграции, backend и показывает QR для телефона; кнопка «Остановить» завершает запущенный ею сервер.
Для телефона используйте адрес ноутбука из панели, а не localhost. Телефон и ноутбук должны находиться в одной сети.
Если Windows блокирует доступ, один раз запустите `Script/enable-lan.ps1` от администратора (порт 8002, локальная подсеть).
Кнопка «Подключить датчик через интернет» создаёт временный Cloudflare URL и QR. Теперь эта ссылка предназначена для Android sync: POST /api/v1/sync доступен по отдельному ключу; чтение измерений и карты через туннель закрыто. Карта остаётся на локальном адресе ноутбука. Кнопка «Копировать ключ Android» копирует ключ из Script/.tools/sync-token.txt; его нельзя публиковать.
Не закрывайте панель во время демонстрации. Копирование QR само по себе сервер не запускает.

Нужны Python, совместимый с backend, и Node.js, совместимый с текущим Vite; ориентируйтесь на manifests и lock-файлы.
На этом ноутбуке существующее backend/.venv сохранено. Не пересоздавайте его без причины.

```powershell
& ./air-quality-backend/.venv/Scripts/python.exe -m pip install -r air-quality-backend/requirements-dev.txt

Pop-Location

# Проверка запуска без открытия окна:
powershell -NoProfile -ExecutionPolicy Bypass -File ./Script/server-panel.ps1 -CheckOnly

# Панель или консольный сервер (выбрать один способ):
./Script/server-panel.cmd
powershell -NoProfile -ExecutionPolicy Bypass -File ./Script/start.ps1

# Снимок базы для переноса/публикации:
& ./air-quality-backend/.venv/Scripts/python.exe ./Script/snapshot-database.py
```

Настройки backend: `.env` в air-quality-backend, образец `.env.example`.
`DATABASE_URL` по умолчанию `sqlite:///./air_quality.db`; `HOST`, `PORT`, `API_KEY`, `CORS_ORIGINS` читаются настройками приложения.
Запускайте Python-модуль backend из папки air-quality-backend: относительный путь SQLite зависит от текущей папки.
Панель делает это автоматически и задаёт HOST=0.0.0.0, PORT=8002.
При заданном API_KEY защищённые запросы требуют X-API-Key. Не вставляйте ключи в исходники или README.
Docker Compose внутри backend — отдельный вариант с PostgreSQL и обязательным POSTGRES_PASSWORD; SQLite-панель его не запускает.

## Как идут данные

1. ESP32-C3 SuperMini читает AM2301A и аналоговый MQ-135 и передаёт JSON по BLE в Android.
2. Android принимает уведомления, показывает показания, добавляет GPS, точность, высоту, UTC-время и UUID измерения, сохраняет в Room.
3. Android отправляет пачки на backend по HTTP. Backend сохраняет исходные измерения и результаты обработки в SQLite.
4. Веб-интерфейс читает API с того же адреса, показывает карту, историю, календарь и анализ.

Текущий BLE-контракт рабочего скетча (это не HTTP-пакет):

```json
{"device_id":"ESP32-001","temperature":27.9,"humidity":33.4,"mq135_raw":62}
```

BLE-имя: ESP32-AIR-QUALITY.
Service UUID: 4fafc201-1fb5-459e-8fcc-c5c9c331914b.
Characteristic UUID: beb5483e-36e1-4688-b7f5-ea07361b26a8 (READ/NOTIFY).
JSON отправляется одним уведомлением; приложению нужно согласовать достаточный MTU и подтвердить запись CCCD через onDescriptorWrite.
На ESP32 сейчас GPIO3 — DATA, GPIO0 — MQ-135 через делитель; тип DHT22 сохранён из рабочего скетча, не менять без проверки датчика.
Синий LED распространённой SuperMini: GPIO8, LOW включает. GPS и LoRa сейчас не установлены.
MQ-135 raw — показание ADC, не AQI и не ppm; без калибровки перевод в концентрации недостоверен.

Android-проект хранится отдельно: `../AirMonitor_Android_Project/AirMonitor`.
В нём BLE-логика: `app/src/main/java/com/airmonitor/bluetooth/BleManager.kt`.
Прошивка Arduino в этом репозитории сейчас не хранится. Успешное получение BLE-данных подтверждено пользователем 18 ноября 2026.

## HTTP-контракт

POST /api/v1/sync:

```json
{"measurements":[{"measurement_id":"d0924faa-c5ad-4e08-9a95-0d0d578537f1","device_id":"ESP32-001","temperature_c":27.9,"humidity_pct":33.4,"mq135_raw":62,"latitude":43.2389,"longitude":76.8897,"gps_accuracy_m":8.0,"altitude_m":null,"measured_at":"2026-11-18T17:00:00Z","synced":false}]}
```

Android преобразует BLE temperature/humidity в HTTP temperature_c/humidity_pct.
UUID measurement_id создаётся один раз и сохраняется при повторной отправке. Backend распознаёт дубликаты по нему.
Ответ содержит accepted/duplicates/rejected и построчные results. Android отмечает локальное synced=true только для accepted/duplicate.
HTTP 200 не означает, что приняты все записи. Пачка: 1–1000 измерений.
altitude_m допускает null или число; measured_at требует часовой пояс и нормализуется в UTC.

Основные маршруты (точная схема — /docs и исходники app/main.py):

- GET /api/v1/health → {"status":"ok"}.
- POST /api/v1/sync — синхронизация Android.
- POST /api/v1/import — импорт пачек данных.
- GET /api/v1/measurements — записи с пагинацией limit/offset и фильтрами.
- GET /api/v1/measurements/latest — последнее измерение.
- GET /api/v1/measurements/{measurement_id} — запись по UUID.
- GET /api/v1/map — точки с координатами.
- GET /api/v1/statistics — агрегаты.
- GET /api/v1/calendar?year=2026 — календарь MQ-135 по дням UTC, опционально device_id.
- GET /api/v1/recommendations — ответ not_calibrated, без выдуманных рекомендаций.

Модели: measurements — исходные значения, координаты и время; processed_measurements — результат обработки.
Не импортируйте синтетику повторно «для запуска» и не заменяйте рабочую базу снимком автоматически.
Рабочая база после переноса содержит 72 000 записей. Старая база на 4 800 записей сохранена во внешнем архиве.

## Интернет и фоновый Android — обновление 18.11.2026

1. Запустите Script/server-panel.cmd, нажмите «Запустить», затем «Интернет-ссылка».
2. В Android укажите созданный HTTPS URL и ключ из кнопки «Копировать ключ Android», нажмите SAVE URL.
3. Нажмите START BACKGROUND при открытом приложении и разрешите Bluetooth, геолокацию и уведомления.
4. Появится постоянное уведомление. Можно выключить экран: служба сохраняет BLE-измерения с интервалом 10 секунд, добавляя только свежие GPS-данные (не старше 60 секунд).
5. Отправка идёт из активной службы примерно каждые 30 секунд и через WorkManager при наличии сети. При ошибках — повторные попытки с увеличением паузы. Без сети всё остаётся в Room.
6. Остановка: STOP в приложении или Stop в уведомлении. Принудительная остановка приложения/перезагрузка требуют повторного START BACKGROUND; скрытого автозапуска нет.

Очередь Room не очищается; synced=true ставится только по results со статусом accepted/duplicate и совпавшими index/measurement_id. HTTP содержит snake_case и UTC ISO-8601, а не имена полей Room и Unix-миллисекунды.
WorkManager — резервная доставка; периодический запуск от 15 минут, Android может откладывать его в энергосбережении. Длительный режим зависит и от ограничений производителя телефона; уведомление должно оставаться активным. Сбор удерживает partial wake lock до STOP, поэтому расходует батарею.
Если временная ссылка изменилась после перезапуска туннеля, обновите URL в Android. Ключ сохраняется на ноутбуке; если удалить Script/.tools/sync-token.txt, будет создан новый ключ и его нужно обновить на телефоне.
Ключ передаётся заголовком X-Sync-Token, не в URL. При прямом обращении к защищённому backend это же поле приложения используется как X-API-Key.
Для интернет-сервера приложение требует HTTPS. Ноутбук, сервер и туннель должны оставаться включёнными.
Android-код находится отдельно в ../AirMonitor_Android_Project/AirMonitor: MonitoringService.kt, MonitorRuntime.kt, network/SyncWorker.kt и network/ApiService.kt.
Проверки шлюза: из backend выполнить python -m pytest -q tests ../Script/tests; проверки Android — gradlew.bat :app:testDebugUnitTest :app:lintDebug.

Фактическая проверка фонового режима и HTTPS: Script/docs/INTERNET-BACKGROUND-VERIFICATION.md. Рабочая база теперь пополняется реальными GPS-измерениями; публикацию их в GitHub нужно согласовать отдельно.

## Два QR в панели запуска

Слева «Сайт — открыть в браузере»: постоянное назначение — локальный адрес ноутбука на8002. Выберите его Wi-Fi/хот-спот адрес; телефон должен находиться в той же сети. Копирование ссылки сайта отдельное.

Справа «Датчик / Android — отправка данных»: нажмите «Подключить датчик через интернет», появится отдельный HTTPS-адрес и QR. Этот адрес предназначен для синхронизации, сайт через него не открывается. «Копировать адрес для Android» и «Копировать ключ Android» — отдельные кнопки. В новой сборке Android в блоке «Измерения и сервер» есть «Сканировать QR сервера». Личный QR содержит адрес и sync key; приложение показывает адрес и спрашивает подтверждение, затем сохраняет оба поля. Не публикуйте и не пересылайте личный QR посторонним. Обычный QR сайта не содержит ключа и не подходит для настройки Android. ESP32 продолжает передавать данные телефону по Bluetooth.

Интернет-синхронизация больше не заменяет QR сайта. Изменения панели загружаются при новом запуске Script/server-panel.cmd. Закрытие работающей панели предлагает остановить сервер; после повторного запуска временный HTTPS-адрес может смениться — обновите его в Android. Ключ без необходимости не меняйте.

### Как включить интернет-показ на демонстрации

1. Откройте Script/server-panel.cmd и нажмите «Запустить».
2. В левой колонке сверху нажмите «Включить демо-доступ клиентам».
3. Дождитесь адреса https://...trycloudflare.com — левый QR переключится на сайт. Его можно дать зрителям из любой сети. Ключа Android в нём нет.
4. После показа нажмите «Отключить демо-доступ»; левый QR вернётся к локальной ссылке. «Остановить» выключает backend и оба туннеля.
5. Для отправки измерений отдельно используйте правую колонку «Датчик / Android» и её личный QR. Не давайте его зрителям.

Зрительский туннель разрешает только белый список GET: сайт/assets/favicon, health, dashboard/snapshot, measurements/calendar/map/statistics/recommendations. POST/PUT/PATCH/DELETE через зрительскую ссылку закрыты. Изменения базы/импорт недоступны. Поддерживается приватный backend API_KEY при проксировании чтения. Раскрытие реальных GPS на сайте явно разрешено для демонстраций; 20.11.2026 пользователь после обсуждения GPS отдельно поручил полную резервную копию в GitHub на случай потери ноутбука, включая текущую базу72084. Копия включает backend/frontend, скрипты, airmonitor-android/ (исходники Android без SDK-путей и кешей), Script/releases/AirMonitor-latest.apk, прошивку второй ESP32 и согласованный Script/data/air_quality.db. Снимок20.11.2026 содержит72084измерения, включая84реальныхGPS, опубликованных по прямому указанию пользователя. Это текущая резервная копия, а не только демонстрационная синтетика. .env, sync keys, debug signing keys, рабочая живаяSQLite/WAL, логи и кеши не входят. Для восстановления backend скопируйте согласованный снимок в air-quality-backend/air_quality.db при остановленном сервере; не затирайте существующую рабочую базу с новыми данными. На новом ноутбуке установите зависимости/AndroidSDK/JDK17 и пересоздайте локальные настройки. Личные ключи/настройки нужно хранить отдельно.
