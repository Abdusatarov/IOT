# Часовые средние на сервере

Режим HOURLY_STORAGE=true применяется к новым POST /api/v1/sync и /api/v1/import. Данные телефона и прежняя история сервера не удаляются.

Для каждого device_id и часа UTC [HH:00, HH+1:00) хранится одна обновляемая запись. Пока час не завершён, это промежуточное среднее. Показания с опозданием обновляют свой исходный час. Для каждой величины сохраняются собственные сумма и число пригодных значений: средние партий не усредняются друг с другом. Дробное среднее MQ-135 не округляется до целого. В API mq135_raw для часовой записи означает среднее исходных ADC отсчётов, не ppm/AQI. hour_start и sample_count обозначают час и число принятых пригодных сообщений; measured_at — время самого позднего принятого измерения этого часа.

MQ-135: 0, отрицательные и значения >4095 не включаются в среднее. AM2301A: температура вне -40..80°C и влажность вне 0..100% исключаются. Температура0°C, влажность0% и координаты0 сами по себе допустимы. Одновременная тройка MQ=0, температура=0, влажность=0 считается сбоем сообщения. Это эвристика качества входа, не диагностика ESP32 или калибровка. Полностью пустое/непригодное сообщение подтверждается accepted с пояснением в results.details и не создаёт измерение, чтобы Android не повторял его бесконечно.

Для каждой исходной measurement_id хранится компактная запись sync_receipts: UUID и ссылка на часовую запись. Это необходимо, чтобы повторы, параллельные пачки, перезапуск сервера и повторная синхронизация телефона не увеличивали среднее. Это не полный журнал исходных измерений. Нельзя удалять receipts, пока клиент может повторить эти UUID. Пример проверки на двух временныхSQLite:360сообщений за час дают229376байт в прежнем режиме и65536байт в часовом(включая receipts),1запись измерения вместо360. Экономия для реальных данных зависит от частоты и размера базы.

GPS: последняя полная пара latitude/longitude за час, вместе с точностью и высотой именно этого сообщения. Отсутствующая более поздняя GPS пара не стирает последнюю известную. gps_sample_at показывает время координаты; это не точный маршрут и не координата среднего показания. При движении детализация маршрута за час теряется.

Миграция0002 только добавляет nullable столбцы, уникальный индекс device/hour и receipts; прежние строки и ID сохраняются. В часовом режиме старые недопустимые значения исключаются из выдачи/API, статистики и календаря без удаления исходников. Схема0001 и старые полностью подробные строки не уплотняются автоматически. Для их преобразования нужен отдельный проверяемый план с резервной копией.

Settings по умолчанию сохраняет прежний подробный режим для совместимости; в локальном.env и новом.env.example включён HOURLY_STORAGE=true. После миграции перезапустить сервер через Script/server-panel.cmd. Нельзя восстанавливать старую базу поверх новой с поступившими измерениями. Автоматический downgrade0002 запрещён: восстановление выполняется из проверенной резервной копии при остановленном сервере.

Android менять не требуется: исходные index/measurement_id и статусы accepted/duplicate/rejected сохранены. Room телефона по-прежнему содержит подробные измерения. Часовая запись получает стабильный UUID; GET measurement по исходному UUID возвращает соответствующую часовую запись. Физическую проблему с MQ-135 следует отдельно проверить по питанию, проводке и ADC; фильтрация не исправляет аппаратный сбой.
