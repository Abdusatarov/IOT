# AlmatyAir — интерфейс Air Monitor

React 19 / TypeScript / Vite, Leaflet для карты, Recharts для графиков, Lucide для иконок.

## Запуск проекта

Основной запуск всего проекта: `../Script/server-panel.cmd`. Backend отдаёт собранный сайт на http://localhost:8002/ . Телефону нужен адрес ноутбука из панели запуска, а не localhost.

Для разработки фронтенда (Node.js 22.12+):

```sh
npm ci
npm run dev
```

Vite перенаправляет `/api` на локальный backend `127.0.0.1:8002`. Backend должен быть запущен отдельно панелью. После правок для основного сайта выполните:

```sh
npm run lint
npm run build
```

Готовая папка `dist` обслуживается FastAPI; открытие index.html двойным щелчком не подходит. `npm run preview` показывает сборку отдельно, но для API используйте основной адрес backend или Vite dev с proxy.

## Страницы и данные

- `#/overview`: показания, сравнение периодов, график и мини-карта.
- `#/map`: датчики, последние 24 часа, цветной слой, палитры, панель выбранного устройства.
- `#/analytics`: поиск, сводка, история четырёх показателей, масштабирование и перемещение графика. `?device=...` в hash выбирает устройство после перехода из карты.
- `#/calendar`: годовая сетка, устройство, суточные средние и сведения за день.
- `#/about`: описание проекта и ограничений измерений.

`scopedReadings.ts` загружает данные по назначению страницы. Карта получает `/api/v1/dashboard/snapshot?hour=0..24`: последнюю запись каждого устройства до выбранного момента, общий диапазон raw и список устройств. Это не вся история; тихие датчики не теряются. История выбранного датчика запрашивается отдельно через `/api/v1/measurements` с device_id/from/to и полной пагинацией только внутри 24ч. Обзор получает тот же снимок и записи выбранного/предыдущего периода с from/to; мини-карта не запускает отдельный полный запрос. Календарь — готовые итоги `/api/v1/calendar?year=...&device_id=...` плюс небольшой снимок для списка устройств. «О проекте» не запрашивает измерения. `live.ts` с полной пагинацией остаётся для Анализа и сравнения всей истории; при уходе из него ненужный запрос отменяется. Обновление раз в60секунд. Длинные периоды и Анализ всё ещё могут требовать много записей — это отдельная дальнейшая оптимизация.

`comparison.ts`, `analysisData.ts`, `mapData.ts` сохраняют прежние расчёты. API-время UTC, графики и записи — Asia/Almaty; суточные агрегаты календаря остаются UTC с явной подписью.

MQ-135 raw — некалиброванный исходный сигнал. Перевода в AQI, ppm или концентрацию частиц нет. Цветной слой карты — приблизительная интерполяция между датчиками, не измерение в каждой точке. Демо-бейдж появляется только по флагу is_synthetic=true от API. В рабочей базе могут быть реальные данные и GPS: не публикуйте её без отдельного разрешения.

## Где менять интерфейс

- `src/components/AppShell.tsx`, `shell.css`, `navigation.ts`: навигация, темы, мобильная панель.
- `design-system.css`, `components/UI.tsx`: общие токены и элементы.
- `Overview.tsx`, `overview.css`, `AirChart.tsx`: обзор и сравнение периодов.
- `MapPage.tsx`, `AirMap.tsx`, `SensorPanel.tsx`, `map-page.css`, `map-base.css`: карта и панель датчика. Тёмный фильтр применяется только к тайлам, не к значениям или цветному слою.
- `Analysis.tsx`, `HistoryChart.tsx`, `historySeries.ts`, `analysis-page.css`: анализ и подробные графики. Полноэкранный режим через CSS работает без Fullscreen API; Escape закрывает. Скрытие списка сохраняется в almatyair.analysisListHidden. Паузы между записями больше 6 часов разрывают линию только при отображении, не меняя данные и статистику.
- `LiveCalendar.tsx`, `calendarData.ts`, `calendar-page.css`: календарь. Цвета распределены по рангу суточных средних выбранного года (5 групп, одинаковые значения одного цвета). Это относительное сравнение дней, а не равномерные диапазоны min/max или пороги безопасности; сами средние берутся из API без изменений.
- `time.ts`: единый формат времени и чисел.
- `DesignPreview.tsx`: служебный просмотр компонентов по `?design-system=1`, без загрузки данных. Это не альтернативный сайт.

Общий контекст для будущей ИИ — `../README.md`, исходный дизайн-brief и журнал этапов — `../Script/docs/REDESIGN-BRIEF.txt` и `REDESIGN-PROGRESS.md`. Не меняйте протокол Android/BLE и расчёты ради оформления. Секреты, рабочая база, node_modules и dist не предназначены для автоматической публикации.
